# 开发迭代记录

## 2026-10-15 · 第一阶段

### 用户任务与边界

建立大学《移动信息化》课程项目 GuJi ID 的最小可运行基础。采用 Python FastAPI、Jinja2、HTML/CSS/JavaScript 和 SQLite 内置 sqlite3。建立四张核心表、四份 CSV 模板、整批导入脚本、基础自动测试与使用文档。需保留同名人物独立身份，所有正式证据须有真实依据，证据不足保持不确定。

明确不开发后续检索/消歧、RapidFuzz、爬虫、自动发现、AI 语义消歧、知识图谱、OCR、复杂后台或权限系统。

### 迭代 1：检查环境与实现约定

- 工作目录只有空的 outputs/、work/，无可复用代码；Python 3.12.10 可用，项目依赖尚未安装。
- 项目放在 outputs/guji-id/，构建与测试工具放在工作区 work/，不写入用户主目录。
- 无外部 Claude CLI 调用，无子代理任务。
- 以模块划分连接、建表、规范化和导入，使用 FastAPI 应用工厂及 lifespan 初始化。
- 状态使用 pending/verified/disputed/rejected，原始姓名与原文保留，规范化仅 NFC 与首尾空白清理。

### 迭代 2：数据库与导入

- 四张表使用 TEXT 稳定主键；外键每次连接开启，删除/更新引用对象受限；名称索引不全局唯一。
- 不确定人物信息使用 NULL；年份可为负数，不允许无公元意义的 0 年或生年晚于卒年。
- 四份 CSV 必需，允许仅表头。检查编码、表头、行宽、必填字段、枚举、年份、URL 格式、重复 ID 和外键。
- 固定依赖顺序导入；同 ID 同内容跳过，同 ID 不同内容失败，不提供静默更新。
- BEGIN IMMEDIATE + 整批提交/回滚；已核对别称要求已核对直接支持证据；已核对证据要求可定位来源。
- URL 与状态检查不等同于内容真实性审核，人工核对是必要前提。

### 迭代 3：首页与测试

- 首页使用空数据状态和实际数据库数量，提供四份模板下载与健康检查按钮；不预置虚构历史数据。
- 自动测试使用 pytest 临时目录与显式传入的数据库，夹具标为 TEST_ONLY；不进入正式统计。
- 首轮执行：69 passed；无失败；一条 Starlette TestClient 使用 httpx 的第三方弃用警告。
- 固定本次验证的直接依赖版本并保存完整锁定清单；补充安装、启动、导入、字段与核对边界文档。

### 最终验证
