# GuJi ID | 数字古籍视觉规范 v0.1

## 设计定位

**宋刻书卷 × 数字人物考据**。关键词：摄影中的实体古籍、幽暗书房与暖色侧光、刻本排版、宣纸肌理、朱批考据、功能严谨。**禁止**通过左右 Hero + 三块卡片的通用 SaaS 架构替代主题设计。

## 三幕叙事

- **I｜暗室启卷（0–32%）**：暗墨背景 `#15130f`；真实古籍照片在右，标题和检索在左，始终允许用户跳过动效。
- **II｜镜头入卷（32–79%）**：逐步扩大镜头，书页特写覆盖实体书照片。局部朱批/人物标记浮现，滚动推进而非定时自动播放。
- **III｜辨人考据（79–100%及下方人物区）**：背景从影调过渡至纸张 `#eee5d3`，内容回归清晰的查询档案排版。

进度百分比仅是当前原型的初始时间轴分配，正式开发可以按实际滚动体验优化。

| 书页底色 | `#eee5d3` |
| 正文墨色 | `#29231d` |

| 温暖纸上辅色 | `#79634b` |
| 古籍金 | `#c3ab87` |

- 展示中文：优先 **Noto Serif CJK SC / 思源宋体**；可回退至宋体系列。避免极端细字重和过多书法字。
- 交互控件用现代可读字体，字号不低于移动端可辨认范围；英文字样、卷次号使用 Georgia 等稳重的衬线字。
- 具体组件实现以 `styles.css` 为准，所有真正的 UI 文本都由 HTML 渲染。

## 动效规范

- 启卷主效：缓慢推进/轻度视觉缩放，不设置不可跳过的遮罩片头。
- 查询/导航反馈：200–300ms，使用 `opacity`/`transform`；鼠标悬停以朱线、轻微抬升表现。
- 纸白过渡：光影转入暖色纸张，不能只有两张完全无关照片直接交替闪动。
- 降动效模式：关闭大幅缩放，保留内容可见、可操作；降低手机端图层和过度动画。

## 首屏与研究区的区别

- 首屏：高质量摄影主导、戏剧性空间光、标题与搜索简洁。
- 档案区：扉页/笺纸、无障碍文本、原文真实、来源真实、争议标注清楚、同名人物消歧。
- 不能将 AI 生成的错字、虚构引文或合成书页纹理当作史料，必须接正式数据。

## 资产处理

`assets/antique-books.webp`、`book-detail.webp`、`archive-page.webp` 是从本次会话已确认的 AI 视觉设计稿裁切的**氛围参考层**；`rice-paper.webp`、`film-grain.png` 为本地程序生成的纹理，不引入未经明确许可的外站素材。正式发布建议替换为核实使用权限的真实馆藏图像，保留分层机制。


## V0.2 新增：双模式古籍内容策略（强约束）

- **A 通用氛围＋动态题签**：静态素材仅提供材质和光影；姓名、字号、时代、称呼状态、朱砂框和引文由独立 DOM/SVG 渲染。固定含「李白」的 `assets/archive-page.webp` 仅是 V0.1 静态参考，**不得在非李白人物界面当作其原文书影**；即使是李白也不能当作历史证据。
- **B 可追溯的真实馆藏书影**：要有可信的馆藏/来源链接、图像许可、人物规范 ID 与证据 ID 的明确映射。单凭名字一样不能使用；来源无法核实则不用 B。
- 朱砂定位框须有人工核对的相对坐标；没位置就不画。书影不存在或失败自动回退 A，并保留真实文字证据。
- 已生成的 `index.html`、`styles.css`、`animation.js` 是 v0.1 视觉原型，不代表 A+B 已开发完成，须按最新 `CODEX_HANDOFF.md` 升级。
- 页面标明「视觉示意／数字题签」与「真实古籍书影」的差别。可展示经核验的文献引文，但不可为渲染填充假书页文字。
- 正式主站 UI 的视觉效果以保留三幕光影和纸白考据为底线；不要因接入数据库而退化为灰色表格和方块卡片。
