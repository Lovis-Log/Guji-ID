# GuJi ID — 沉浸式首页 Design Lab v0.1

## 已实现

- 第一幕「暗室启卷」：古籍实物摄影视觉、侧光、标题、**真正可以输入和提交**的检索 UI。
- 第二幕「镜头入卷」：随滚动推进镜头、切换古籍文字特写、出现朱批标注。
- 第三幕「古籍考据」：深色场景过渡为纸白古籍界面，人物样式页以及可切换的「人物信息 / 称呼关系 / 文献证据」标签。
- 可点击的快捷检索词、键盘可访问弹窗、响应式手机布局、`prefers-reduced-motion` 降动效模式、离线运行。

> **这是不依赖原数据库的视觉实验页面，不是新的 GuJi ID 后端。** 不会产生虚构数据库检索结果，也不添加未经核实的文献引文。人物卡片是显著标注的示例，不代表真实数据库的录入状态。

## 运行

方案一：直接双击 `index.html`（大多数浏览器可正常浏览，部分浏览器会限制本地脚本加载）。

方案二（推荐）：在此目录打开终端：

```sh
python -m http.server 8765
```

然后在浏览器访问 http://127.0.0.1:8765/。页面和动效所需素材已全部本地打包，不依赖 CDN / 云端服务。

## 接到现有 GuJi ID 中

1. **只用新的 Git 分支**（如 `feature/immersive-home`）；备份现有首页模板、静态文件、相关路由与既有截图。
2. 不碰 SQLite 数据库、模型、采集/核验/入库代码；仅改首页模板与静态资源。先检查正式项目的真实首页和搜索路由，**不要假定是 `/search`**。
3. 将 `assets/` 拷贝到现有项目规范的静态目录，并调整 `styles.css` 中的静态相对路径；将 HTML 按原技术栈改为模板而非复制成第二套应用。
4. 在 `config.js` 中设置 `searchUrlTemplate`，填写**已经核实存在**的检索地址和 `{query}` 占位符。用户提交时会执行真实跳转；如果需要 POST 请求、复杂查询参数或 API 搜索结果页，应在 `animation.js` 的 `search()` 内适配原有逻辑。
5. 「李白」档案标签为**展示占位**，应由正式库真实人物数据动态渲染；文献证据严禁自动伪造。保持同名消歧、证据出处、待考状态原样。
6. 检查全局 CSS 冲突、导航可用性、原有所有回归测试；最后再合并至主分支。

## 技术说明

- 当前版本为**无依赖、离线可执行的原生 JS**：使用 `requestAnimationFrame` 将滚动量映射到镜头、透明度、纸白转场；无 WebGL / 巨大依赖。
- 如果正式项目已集成 GSAP，可将 `updateScene()` 迁移为 GSAP ScrollTrigger 时间轴，但不是必须。**本原型没有声称已安装 GSAP**。
- 画面取材于本对话此前确认的 AI 视觉关键帧，裁切为单独场景摄影层（`antique-books.webp`、`book-detail.webp`、`archive-page.webp`）；其他文字、搜索框、卡片、标注为**浏览器真实 HTML**。原始 AI 书页文字仅为氛围图，不能作为史料或数据库证据。
- 正式发布建议以已获使用许可的真实古籍摄影/馆藏扫描替换 AI 图片，并核对文字，不展示误导性史料。
