# GuJi ID｜沉浸式首页改版 + A/B 动态古籍展示（Codex 执行指令 V0.2）

你正在维护 **GuJi ID（古籍人物规范档案）**，现有系统使用 FastAPI，并具有正式人物、称呼关系、证据、同名消歧及采集核验流程。此次任务是**保留现有业务与数据，仅升级前端视觉和展示方式**。

我已经确认 `guji-id-design-lab/` 的三幕美术方向：**第一幕真实古籍的暗室电影感 → 第二幕随滚动推进至书页特写 → 第三幕明亮纸白的人物考据**。不得重新设计成“米白背景 + 标题 + 搜索框 + 三个功能卡片”的通用 AI/SaaS 模板。保留电影光影、精致书页纹理、宋刻版面、细朱批以及滚动叙事。现在新增明确决定：**采用 A + B 双模式动态古籍展示，彻底解决静态图片中固定「李白」的问题。**

## 一、先准备并核实环境

1. 请先确认项目仓库、前端框架与模板、首页路由、真实检索路由/API、人物详情 URL、静态目录和测试命令。**禁止猜测 `/search` 路径、API 字段或数据库表结构。**
2. `guji-id-design-lab/` 是我已确认的独立视觉原型，里面包含 `index.html`、`styles.css`、`animation.js`、`assets/`、`screenshots/`、`DESIGN_SPEC.md`、`README.md` 与 `.agents/skills/guji-id-visual/SKILL.md`。请先读取，再按实际项目技术栈迁移，不要重新生成一套毫无关联的 UI。注意：它当前是 **V0.1 静态样式原型**，不是已经完成 A+B 动态接入的正式网页。
3. 在项目已有 Git 版本控制且工作区安全的前提下建立 `feature/guji-immersive-ab` 分支（或等效隔离工作树）。先截取旧版首页、检索结果、人物档案截图，记录相关测试基线和正式库数据快照/行数。禁止无意覆盖未提交更改。
4. 项目专属设计 Skill 位于 `.agents/skills/guji-id-visual/SKILL.md`，应在原项目根目录被 Codex 识别并使用。其他前端设计 Skill 可按实际可用情况选用，不要为了安装大量工具而阻塞开发。**如果环境有明确可调用的 subagent**，将截图视觉审查与无障碍/回归检查委派给它们以节省主 agent 上下文；没有就正常完成，不能假称调用过。这个 UI 任务不需要耗费 DeepSeek API 做美学判定。

## 二、必须实现的页面和动效

**第一幕 · 暗室启卷**：电影化暗色书房、真实古籍实物氛围、暖光、非对称版式；真实的 HTML 标题、导航与首屏搜索始终可见、可操作。不要把整张合成设计稿当背景图以冒充交互界面。

**第二幕 · 镜头入卷**：滚动驱动古籍放大、局部聚焦、纸张逐渐占据画面，朱砂标记浮现，保持连续视效；不要简化成无关图片生硬切换。当前原生 JS + CSS 方案可以继续使用；只有 GSAP / ScrollTrigger 确实改善体验时才引入，不要为炫技加入 Three.js / 粒子特效。

**第三幕 · 辨人考据**：从暗色平滑过渡到纸白色古籍考据阅读界面。人物名、字、号、时代、身份、称呼、证据、来源状态都来自原系统的**真实数据**，有多少展示多少；不完整信息使用「未收录／待考／暂无可核验出处」等准确措辞，不要将未知写成确定。

## 三、A + B 双模式古籍展示（本轮最重要的新增需求）

### 模式 A：通用古籍氛围 + 动态人物题签（默认与回退）

- 首页未指定人物时，可以呈现**明确标为示例**的精选人物，也可以先展示中性的泛古籍氛围；一旦用户选择/打开人物档案，姓名、字、号、时代、状态必须从当前**人物规范 ID**读取并动态更新。
- 原型的 `assets/archive-page.webp` 内已固定嵌入「李白」二字，`index.html` 中的 `.ink-focus`、`.archive-aside`、`.identity-grid` 等也含有固定的李白示例。**必须逐一检查、改造，绝不能对苏轼、王珪等人物继续显示含「李白」的古籍页面作为其专属书影**。
- 用中性、不指向特定人物的纸张纹理/古籍氛围图承载视觉；人物姓名、字号、身份标签、朱砂框等由 **HTML/CSS/SVG 独立图层**渲染，避免把人物姓名重新烘焙进图片。若模拟古籍竖排排版，应明确是「数字题签/交互展示」，**不能伪装成古籍原文扫描**。
- 如果展示古籍引文，必须引用正式库中可定位且有出处的文本。没有已证实的原文时，**不要用 AI 编出仿古句子填满书页**，可用不含可识别人名/伪引文的纹理或者留白。
- 搜索本身应走已有真实检索行为，而不是通过前端把输入字符串直接伪装成检索成功的人物身份；有多个同名结果时先展示独立候选，让用户选择规范 ID。

### 模式 B：真实可追溯的馆藏书影 + 原文定位（优先，条件满足才显示）

- 只有当**具体人物规范 ID**与**具体证据 ID/来源**存在可信关联，且书影有明确出处与可使用的资源地址时，才可在该人物的相关证据处展示真正的古籍扫描图。
- 书影信息至少包含：`person_id`、`evidence_id` 或等价可追溯关联、文献题名/卷次（来源有则展示）、藏馆或资源提供方、书影页面 URL / 本地资源路径、原始来源页链接、授权/使用说明、审核或核对状态。不要从名字相同推断同一个人物，也不要伪造缺失元数据。
- 当人工核实了书页上的具体姓名位置，可用**归一化坐标**（相对原图，0–1）绘制独立 SVG/HTML 朱砂框，随图片缩放准确贴合。没有核实定位坐标时**不画假框**，可展示整张原图并标明「尚未定位到页内文字」。
- 优先重用正式库已具备的数据字段/接口。如数据库没有书影字段，**先在表现层建立独立、只读、可为空的书影索引清单**，以已有规范 ID/证据 ID 关联，避免擅自迁移 SQLite 或更改核验模型；如确需修改数据库或正式后端契约，列明方案并暂停等待批准。
- 书影资源缺失、授权不清、关联未核实、加载失败时自动回退 A，并准确显示「暂无可展示的真实书影」等信息。**不能把 AI 生成的 `archive-page.webp` 当作模式 B 的真实馆藏扫描页。**
- 本轮**不要求为数百名人物搜齐真实书影**：先实现完整的 B 展示接口/索引/回退逻辑；仅对已能核实出处和使用许可的少量资料展示真实 B 案例。没有符合条件的 B 案例就如实报告「零条 B 可用书影」，绝不伪造演示成功。

### 两种模式的统一视觉

电影化首页保留，进入档案后采用浅色纸白阅读排版；A 与 B 在同一人物档案组件内无缝切换：有真实可信的书影时展示 B，否则展示 A。真实书影、数字题签、原文证据在文案和可访问性标签中必须区分，不得误导用户认为装饰图像是史料。

## 四、接入正式系统的约束

1. 用**已经验证存在**的真实检索入口连接首屏搜索、快捷人名、结果列表、人物详情；删除正式 UI 中的“仅演示/尚未连接”弹窗。搜索框支持回车、按钮与键盘，空输入不提交。
2. 所有姓名、时代、字、号、别称、称呼关系和来源信息从规范实体与真实证据读取；禁止依据搜索字符串臆造字段。保持同名不同身份独立，特别测试「王珪」对应的多个身份。未确认的称呼关系不得视觉上表现为已核实。
3. 维护人物详情与证据的原有可访问路径，保留或改善筛选、返回、来源查看、证据核验状态标识。首页可沉浸式，检索与考据界面必须清晰高效，避免重动画阻碍阅读。
4. **严格禁止**修改正式 SQLite 数据内容、表结构、采集脚本、DeepSeek 核验流程、自动入库规则、身份消歧判定和证据真伪结论。数据/接口缺口优先在展示层优雅降级；确需跨越此边界必须停下说明。

## 五、分阶段执行，不要直接全站重写

- **P0 勘察与基线**：列出实际模板/路由/数据入口，检查 `design-lab` 的固定人名位置、素材性质和现有风险，保存旧版截图，基线测试与数据计数。
- **P1 Design Lab V0.2**：保留三幕视觉，把 A 模式的姓名文字变成真正可切换的独立 DOM 图层；实现 B 的书影组件和可为空的只读映射、校验与 A 回退；用真实规范 ID 驱动人物上下文，若未接正式 API 时仅标明示例，不模拟入库事实。
- **P2 前端接入**：复用已有 FastAPI 模板/资源方案接入首页、真实查询、人物列表与证据详情；原始 `design-lab/` 留作可运行的视觉对照，不另起一套互不相干的后端。
- **P3 动效和视觉打磨**：修正布局、影像裁切、字体、朱批位置、滚动闪白、浏览器返回与移动端体验；尊重 `prefers-reduced-motion`，保证低性能设备仍能查人。
- **P4 实测和交付**：浏览器截图、录屏或滚动关键帧、自动化交互、全量现有回归测试、只读数据库一致性检查，附文件路径与执行结果。

## 六、必须验收的场景

| 场景 | 必须通过的行为 |
| --- | --- |
| 首页首次打开 | 三幕电影化构图完整；不需要等待动画才能搜索 |
| 搜索李白、苏轼、文徵明 | 走真实搜索；进入正确的人物规范 ID；题签字段随人物变化 |
| 搜索王珪 | 同名人物分别列出；不得误合并，不能用搜索词直接决定身份 |
| 页面展示非李白人物 | 古籍氛围里不得残留误导性的固定「李白」人物文案或专属书影 |
| 已核实真实书影 | B 模式显示原图、出处/授权、正确的证据关联；坐标未经核验不得假高亮 |
| 无书影/关联不明/加载失败 | A 模式正常渲染，保持真实文字证据，给出准确状态 |
| 人物字段缺失/关系待考 | 不填假数据；不把待考画成已证实 |
| 桌面/移动设备 | 1440×900、390×844 截图；建议补测 320 宽度和常见笔记本尺寸，无横向溢出 |
| 动效与交互 | 连续滚动、回滚、键盘、搜索、导航、标签正常；无明显闪白/JS 错误 |
| 辅助功能与性能 | `prefers-reduced-motion`、焦点可见、足够文字对比度、图片替代文本；资源不会明显拖慢首屏 |
| 数据安全 | 原有数据库内容、人物身份、称呼关系、证据记录和已有回归测试均不被本次 UI 改动破坏 |
